## Build, analysis and dependency problems

- The zero-diagnostic gate fails: `dart analyze --fatal-infos --fatal-warnings` exits 1 with 6 `deprecated_member_use` infos, all `'EquatableMixin' is deprecated and shouldn't be used. use Equatable as a mixin instead`, at lib/src/domain/entities/attachment.dart:4, folder.dart:5, link.dart:4, note.dart:7, property.dart:13, vault.dart:6 under equatable 2.1.0. Recommended: keep `Equatable` and drop the mixin (`class Note extends Equatable`, mixin-equality is what `deprecated_member_use` is steering away from); alternative is pinning `equatable` below the deprecation, which only defers it. Either way the 6 files change together, and `props` stays hand-written.
- There is no CI: `.github/workflows/` does not exist in the repo, so neither `dart analyze --fatal-infos --fatal-warnings` nor `dart test` runs on push or PR, and the failing gate above went unnoticed since 1.2.1. Pending: add the workflow.
- `dart_arch_test` is not in `dev_dependencies` (pubspec.yaml:25-28 lists only `lints`, `test`, `shouldly`), so the package-boundary-direction and cycle-freedom gate is absent.
- The README's usage samples would not compile against the shipped API: `vault.createNote('Hello')` in the "API Style" and "Usage" sections needs `createNote(title: 'Hello')`, and `vault.createFolder(name)` likewise (`createNote` and `createFolder` take named params - lib/src/api/obsidian_api.dart:142, :178), so a reader's first copy-paste fails.
- The README API table's `ObsidianVault.create(path: 'path', name: 'name')` is right but the surrounding prose is not: `ObsidianVault.create` is a factory with named params at obsidian_api.dart:41, and the table's `vault.createNote(title, content)` shorthand does not match the named signature at obsidian_api.dart:142.
- The README's `TaskEitherExt<R, L>` snippet reverses fpdart's parameter order - fpdart declares `TaskEither<L, R>` - so the extension as written does not type-check against the values it is called on.
- The README install snippet pins `obsidian_vault_datasource: ^1.1.0` while pubspec.yaml:4 is `version: 1.2.1`, so the doc tells a reader a version two releases behind.
- `createIfMissing` is documented and accepted but never implemented: it is stored on `Link` (lib/src/domain/entities/link.dart:13) and its doc comment promises "creates target note if it doesn't exist" (lib/src/api/obsidian_api.dart:493), but grep finds the flag only in the `Link` constructor, `copyWith` and `props` - nothing reads it and no note is ever created.
- `ObsidianNote.updateTitle` (lib/src/api/obsidian_api.dart:443) cannot actually rename a note: `_persistNote` (obsidian_api.dart:521) writes to `_note.path`, the pre-rename path, so the file keeps its old name while its heading changes, and the vault's note list is re-keyed by the new title only.
- `Note.toMarkdown` / `Note.fromMarkdown` are not a lossless round trip: `fromMarkdown` trims the body (lib/src/domain/entities/note.dart:129, `.join('\n').trim()`), so trailing newlines and leading blank lines are lost on every read.
- Malformed frontmatter fails silently: `_parseYamlSimple` swallows the parse error with `catch (e) { return {}; }` (lib/src/domain/entities/note.dart:176), so a broken frontmatter block is indistinguishable from no frontmatter at all and no failure is reported.
- `_getFileType` and the media-extension lists are duplicated three times - lib/src/api/obsidian_api.dart:303, lib/src/data/repositories/attachment_repository.dart:77 (with the lists at :13-23) and a third copy of the lists as `isImage`/`isVideo`/`isAudio`/`isPdf` getters in lib/src/domain/entities/attachment.dart:33-42 - so adding one file type means three edits kept in step by hand.
- `ObsidianVault._attachments` (lib/src/api/obsidian_api.dart:24) is a mutable field reassigned inside the TaskEither closures at obsidian_api.dart:224, :257 and :283, so the otherwise copy-on-write API carries hidden state that two callers of the same instance can observe.
- `test/benchmark_test.dart` is the only test file that uses `expect()` (9 call sites: lines 45, 46, 68, 90, 115, 140, 163, 188, 206) and does not import shouldly at all, while the other 7 test files assert with shouldly.
- `example/*.dart` (4 files: attachments, create_vault, read_vault, watch_vault) each open with `// ignore_for_file: avoid_print`, a blanket suppression, and nothing exercises them - no test, no CI - so they are unverified claims about the API.
- The benchmark suite asserts wall-clock budgets (2000 ms for a 100-note load at test/benchmark_test.dart:46, 3000 ms for writes at :68) with no warm-up, so it is machine-dependent by construction and will flake on a slower runner.

## Deviations from the dart-flutter-bible

Compared against `staylorx/dart-flutter-bible` `docs/00-compact.md` and `docs/01`-`docs/12`. Each item is a spot where this repo differs from the bible; the bible may itself be wrong, so these are flagged for review and deliberately not auto-fixed.

- Deviation: lib/src/domain/entities/note.dart - the entity is `class Note with EquatableMixin` (note.dart:7) where bible section 4 says `extends Equatable` with `List<Object?> get props`; folder.dart:5, link.dart:4, property.dart:13, vault.dart:6 and attachment.dart:4 all use the mixin form too, and it is the mixin that the analyzer now reports deprecated.
- Deviation: lib/src/domain/failures.dart - one flat `abstract class Failure implements Exception` with 22 non-sealed leaves, where section 4 requires failure hierarchies that are per-layer and closed (domain vs datasource), mapped upward at the repository and exhaustive in a `switch`; `implements Exception` also places an exception type at the centre of the bulls-eye that section 1 keeps exception-free.
- Deviation: lib/src/api/obsidian_api.dart - the public seam hands consumers an un-run `TaskEither<Failure, T>` (`load`, `reload`, `createNote`, `createFolder`, `save`, `refresh`, `loadAttachments`, `getAttachment`, `writeAttachment`, `deleteAttachment`, `readAttachmentBytes`), where section 4's default is `Future<Either<Failure, T>>` terminated by `.run()` inside the layer; the un-run form is allowed only if declared, and neither the barrel doc comment (lib/obsidian_vault_datasource.dart:1-5) nor AGENTS.md declares it - only the README does, so the declaration is one third present.
- Deviation: lib/src/api/obsidian_api.dart - `refresh()` (obsidian_api.dart:188) and `loadAttachments()` (:217) wrap plain already-Either-returning repository calls in `TaskEither(() async {...})` imperatively, using fpdart as a Future wrapper rather than composing with `map`/`flatMap`, which is the shape section 4 describes.
- Deviation: lib/src/api/vault_watcher.dart - hand-rolled `try { } catch (e) { return Left(WatchFailure('$e')); }` (lines 41-57) instead of `TaskEither.tryCatch`; the same hand-rolled shape appears in lib/src/core/usecases/validate_markdown.dart:11-16 (a use case, where sections 4 and 10 permit no try/catch at all) and in lib/src/domain/entities/note.dart:122 and :171 (domain, where it is a hard ban).
- Deviation: lib/src/data/adapters/file_system_adapter.dart - 11 hand-rolled `try { } catch (e) { return Left(...) }` blocks (lines 10-17, 23-26, 32-35, 41-47, 53-58, 64-70, 76-80, 86-92, 98-104, 111-116, 122-129) instead of `Either.tryCatch`/`TaskEither.tryCatch`; section 4 names exactly this shape a violation ("hand-rolled try/catch inside adapters").
- Deviation: lib/src/data/repositories/note_repository.dart - only one repository implementation exists (`NoteRepository` over `FileSystemAdapter`, and `AttachmentRepository` likewise), so section 1's at-least-two-adapter rule and the shared contract suite run against every adapter are both absent, and the de-facto contract is whatever this single adapter does.
- Deviation: lib/src/data/adapters/file_system_adapter.dart - the adapter is a concrete class constructed inside `ObsidianVault.create`/`load` (obsidian_api.dart:42-43, :70-71) and injected directly into repositories and use cases, where section 5 puts the datasource and repository contracts in the domain package and section 3 says domain owns the interfaces; there is no interface for this seam anywhere.
- Deviation: pubspec.yaml - a single monolithic package with `lib/src/domain`, `lib/src/core/usecases`, `lib/src/data` and `lib/src/api` inside it, instead of the section 3 workspace layout of separate domain / usecases / datasource packages, so the inward-dependency rule has no package boundary to be enforced at and `dart_arch_test` would have nothing to assert.
- Deviation: pubspec.yaml - `environment: sdk: ">=3.0.0 <4.0.0"` (pubspec.yaml:14) where section 2 and the bootstrap checklist mandate `'>=3.10.0 <4.0.0'`.
- Deviation: lib/src/domain/entities/note.dart - the domain entity imports `package:yaml` (note.dart:2) and parses frontmatter itself, where section 3 allows a domain package `equatable` and `fpdart` only and section 1 keeps I/O and third-party packages out of the centre; the repo's own AGENTS.md also notes this as a custom parser with the yaml package "available".
- Deviation: lib/src/api/obsidian_api.dart - three public classes in one file (`ObsidianVault`, `ObsidianFolder` at :322, `ObsidianNote` at :397), and lib/src/api/vault_watcher.dart holds an enum, a value class, the watcher and an extension, where sections 2 and 3 require one class per file.

- Deviation: lib/src/core/usecases/create_link.dart - `class CreateLink` carries no `///` doc comment while its sibling use cases do, and undocumented public members are pervasive: `Note.toMarkdown`/`fromMarkdown`/`copyWith` (note.dart:22, :107, :222), `Note.title`/`content`/`properties`/`links`/`path` and their siblings, `Vault.copyWith`, `Vault.allNotes`/`findNote`/`searchNotes`, `Folder.allNotes`/`copyWith`, every `FileSystemAdapter` method, `VaultWatcher.changes`/`dispose`, `Link.toMarkdown`/`fromMarkdown`/`copyWith`, and most `Property`/`Attachment` members - where sections 2 and 10 require a terse `///` on every declaration and public member, use cases included.
